# Задача: редизайн интерфейса LlamaPort

Переработай UI Android-клиента llama.cpp (Flutter). Логику инференса, JNI и платформенные каналы не трогай. Все существующие функции должны остаться рабочими.

## 0. Правила работы

1. Сначала изучи репозиторий: `pubspec.yaml`, структуру `lib/`, стейт-менеджмент, тему, навигацию. Если проект не на Flutter, остановись и сообщи.
2. Работай этапами из раздела 9. После каждого этапа запускай `flutter analyze` и сборку, делай отдельный коммит.
3. Сохраняй Material 3 и dynamic color (Material You).
4. Приложение работает офлайн: шрифты и ассеты только из `assets/`, никакой загрузки из сети в рантайме.
5. Новые зависимости только лёгкие и по делу (допустимо: `animations`, `flutter_animate`). Всё остальное делай на штатных implicit/explicit-анимациях.
6. Не добавляй функций, которых нет в этом документе.

## 1. Главный принцип: анимировано всё

Заведи единый motion-слой `lib/ui/motion/`:

- `motion_tokens.dart`: длительности (микро 150-250 мс, переходы 300-450 мс), кривые, параметры пружин. Никаких магических чисел в виджетах.
- `Reveal`: fade + slide + scale при появлении, параметр `index` для stagger (задержка ~40 мс на элемент, максимум ~400 мс).
- `Pressable`: масштаб ~0.96 при нажатии, пружинный возврат, лёгкий haptic.
- `AnimatedNumber`: плавная смена чисел (RAM, t/s, значения слайдеров, размер KV-кэша).
- `MotionPageRoute`: переходы между экранами (shared axis из пакета `animations`).

Правила:

- У каждого элемента есть анимации появления, нажатия, смены состояния и исчезновения. Статичных элементов не должно остаться: кнопки, чипы, карточки, переключатели, слайдеры, заголовки, иконки, диалоги, снекбары, bottom sheet.
- Списки: staggered-появление, вставка и удаление элементов анимированные (`AnimatedList` или аналог), перестановка плавная.
- Смена цвета, формы и размера всегда плавная (`AnimatedContainer`, `TweenAnimationBuilder`, `AnimatedSwitcher` с осмысленным `transitionBuilder`).
- Уважай системную настройку «убрать анимации» (`MediaQuery.disableAnimations`): декоративное отключай, оставляй короткие fade.
- Производительность: `RepaintBoundary` вокруг робота, стримингового текста и списков. Во время генерации CPU занят моделью, поэтому не пересобирай экран на каждый токен. Держи 60 fps, проверь в profile-режиме.

## 2. Анимированный ASCII-логотип `AsciiRobot`

Существующий логотип остаётся как есть, он источник правды. Не перерисовывай его: преобразуй в матрицу ячеек (`List<String>` или сетку) и рисуй через `CustomPainter` моноширинной сеткой. Если логотип сейчас картинка, конвертируй её в сетку один раз.

API: `AsciiRobot(state, progress, pulse, size)`.

Состояния `RobotState`:

| Состояние | Поведение |
|---|---|
| `sleeping` | модели нет: глаза закрыты, цвет приглушён, медленное «дыхание» яркости |
| `loading` | глаза заполняются по `progress` (0..1) |
| `idle` | модель загружена: моргание, редкие мерцания отдельных ячеек |
| `thinking` | глаза бегают, «антенна» мигает |
| `generating` | «рот» пульсирует на каждый токен (`pulse`) |
| `error` | глаза-крестики, короткая тряска |

Дополнительно:

- Появление: символы ячеек «рассыпаются» (быстрая смена глифов, glyph scramble) и собираются в логотип.
- Тап по роботу: моргнуть или подпрыгнуть.
- Переходы между состояниями плавные (интерполяция, без скачков).
- Тик анимации ячеек ограничь ~12-15 fps: так выходит пиксельный стиль и дешевле для CPU. Плавные движения (дыхание, масштаб) делай на полном fps.
- `Hero` робота между главным экраном и чатом. В чате он уменьшается до аватара ассистента в шапке и пульсирует при генерации.

## 3. Главный экран и навигация

- Верхняя панель: вместо четырёх иконок (чат, карандаш, список, шестерёнка) оставь чип модели (имя + точка состояния) и кнопку «+ новый чат». Чаты и настройки уходят в боковую шторку (`NavigationDrawer`).
- Если текущий чат пуст, «+» не создаёт новый, а оживляет текущий (лёгкая анимация «встряхнуть»).
- Пустое состояние: робот по центру, под ним крупная кнопка «Выбрать модель» (если модель не загружена). Поле ввода «Сначала загрузите модель» убери из пустого состояния. Когда модель загружена, робот «просыпается» и появляются чипы-подсказки.
- Список моделей показывается только в одном месте (по тапу на чип модели, bottom sheet). С главной экрана список убери.

## 4. Выбор модели и RAM

- Карточка модели: имя, квантизация, размер, бейджи «зрение» / «аудио» (если подключён mmproj), метка «влезет / впритык / не влезет» с анимированной сменой цвета.
- Оценка по свободной RAM: размер файла + запас ~15% (+ KV-кэш, если метаданные доступны). Если оценка приблизительная, пиши «≈».
- Корзину убери с зоны тапа: удаление по свайпу или долгому нажатию, с подтверждением и отменой.
- Вместо текста «Свободно X ГБ из Y ГБ» сделай сегментированную полосу RAM (система / модель / свободно) с анимированным обновлением.
- Перед загрузкой: «нужно ~4.7 ГБ, свободно 1.7» и кнопка «Освободить». Кнопка выгружает текущую модель и освобождает кэши приложения. Закрывать чужие приложения нельзя, не пытайся.

## 5. Чат

- Сообщения пользователя: тональный пузырь. Ответ ассистента: на всю ширину без пузыря, аватар-робот слева.
- Размышления модели выделены в отдельный сворачиваемый блок («Размышления» + живая анимация, пока идёт генерация). В финальный текст они не попадают.
- Появление сообщений с пружиной. Стриминг: новые символы плавно проявляются (fade), высота растёт через `AnimatedSize`, без дёрганья.
- Кнопка отправки превращается в «стоп» с морфингом иконки. Рядом чип со скоростью (токенов/с) на `AnimatedNumber`.
- Долгое нажатие на сообщении: действия (копировать и т.д.) в анимированном меню.

## 6. Список чатов

- Исправь превью: сейчас в нём виден текст размышлений («We need to write...»). Хранение размышлений и ответа раздели, превью бери из финального ответа. Если ответа ещё нет, показывай «Думает…».
- Группы «Сегодня / Вчера / Ранее».
- Удаление по свайпу со снекбаром «Отменить».
- Пустые чаты («0 сообщ.») не сохранять.
- На карточке чип модели, которой вёлся чат. Заголовок автоматически из первого сообщения, обрезанный.

## 7. Настройки

Раздели на три анимированно раскрываемые секции:

1. **Поведение**: системный промпт; температура пресетами «Точно» (0.2 / top-p 0.9 / top-k 20), «Баланс» (0.7 / 0.95 / 40, текущие значения), «Творчески» (1.0 / 0.98 / 80) и «Свой» при ручном изменении. Под «Подробнее» раскрываются top-p, top-k, максимум новых токенов, бюджет размышлений.
2. **Память и скорость**: контекст с живой оценкой размера KV-кэша рядом (≈, если метаданных нет), потоки генерации и промпта, пакет промпта, микробатч, Flash Attention.
3. **Продвинутое**: всё остальное.

Контролы:

- Flash Attention: сегментированная кнопка «Авто / Вкл / Выкл» вместо слайдера.
- Слайдеры: точки только там, где значения дискретны. Рядом поле для точного ввода числа, значение анимируется, haptic на шагах.
- Расширение нативного слоя ради оценки KV-кэша не делай. Если нужных данных в Dart нет, показывай приблизительную оценку.

## 8. Тема и типографика

- Оставь dynamic color. Добавь фирменный акцент: пиксельный шрифт (в `assets/`, проверь поддержку кириллицы) только для заголовка логотипа и чисел (RAM, токены/с). Основной текст остаётся системным.
- Формы: единая система скруглений, один «пиксельный» мотив (например, ступенчатые уголки у чипа модели).
- Тёмная и светлая темы должны выглядеть одинаково хорошо.

## 9. Этапы

1. Motion-слой (`motion_tokens`, `Reveal`, `Pressable`, `AnimatedNumber`, `MotionPageRoute`).
2. `AsciiRobot` со всеми состояниями + демо-экран для отладки состояний.
3. Главный экран, навигация, шторка, чип модели.
4. Выбор модели, карточки, полоса RAM.
5. Чат (пузыри, размышления, стриминг, кнопка отправки/стоп).
6. Список чатов + исправление превью.
7. Настройки.
8. Тема, шрифт, финальная полировка, проверка `disableAnimations`.

## 10. Критерии приёмки

- [ ] Все прежние функции работают (загрузка модели, mmproj, чат, остановка, настройки, история).
- [ ] На экранах нет статичных элементов: всё имеет анимацию появления и реакцию на нажатие.
- [ ] Робот отражает все состояния и не роняет частоту кадров при генерации.
- [ ] Превью чатов не содержит текста размышлений.
- [ ] Пустые чаты не копятся.
- [ ] `flutter analyze` без ошибок, сборка проходит.
- [ ] Режим «убрать анимации» корректно ограничивает движение.
